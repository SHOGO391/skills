# lp-copy 共通CLIの実測

2026-10-09、macOS arm64 / Node.js 24 / Playwright 1.64.0 Chromiumで確認。
対象は [指定された公開サイト](https://premiumhumanhp.onrender.com/) のトップページ。
第三者サイトのHTML・画像・フォント・取得URL一覧はリポジトリに含めていません。

## 同じページでの結果

| 方法 | 素材数 | 保存した原本本文の合計 | 取得・変換時間 |
| --- | ---: | ---: | ---: |
| 前回の案件別スクリプト | 295 | 49.93 MB | 同一条件の計測なし |
| 共通CLI quick、初回 | 132 | 18.25 MB | 12.14秒 |
| 共通CLI complete、初回 | 223 | 23.02 MB | 11.87秒 |
| completeをキャッシュで再実行 | 223 | 新規HTTP取得 0 B | 0.36秒 |

MBは10進。本文サイズは圧縮展開後で、通信回線上のバイト数ではありません。
初回quickは前回の保存量に対して約63.4%減。必要素材の優先取得による削減であり、前回保存した全候補素材を同じ範囲で収録した比較ではありません。
quickとcompleteの初回時間差は小さく、実行順・ネットワーク変動があります。quickが常に速いという結果ではありません。

時間は各capture呼び出し内の取得・ブラウザ確認・変換・保存です。依存の初回インストール、AIによるページ調査/actions作成、別コマンドのverify、目視確認、レビューは含みません。前回の総作業時間に対する速度倍率は主張しません。
キャッシュ再実行は1時間のTTL内、同じURL・操作・除外条件、全原本のハッシュ一致を確認し、原本のブラウザ確認を再利用した値です。現在の元サイトを再取得する測定ではありません。更新確認は `--refresh` を使います。

## 確認範囲

- PC 1440×1000 / SP 390×844、全文スクロール。
- メニューを開く/Escapeで閉じる、9種類のAIツールタブ、FAQ開閉。
- quick/completeとも外部通信を遮断したローカルverifyが成功。見出し保持、画像欠け・横はみ出し・HTTP/JS/Consoleエラーなし。
- 元サイトの一部フォントは同梱条件未確認のため除外し、既存のフォールバックを使用。
- 任意APIは取得対象外。元ページで取得失敗していたニュースは同じ組込記事を表示。
- 別ページ、バックエンド、未確認の全モーダルを網羅する検証ではありません。

独立したAIも変更後のスキルを使い、前回のローカルコピーを入力として再コピーしました。取得14.75秒、133素材、18.49 MB。PC/SP・メニュー・FAQ4項目・9タブと原本/ローカルの目視比較に成功しています。
この試用で操作失敗時の再開不能が見つかり、取得開始記録とURLごとのキャッシュ記録を追加しました。現在はactionsを直し、同じ保存先へresumeすると取得済みデータを再利用できます。未訪問のスマホ用素材等は追加で取得します。

## 継続的な検証

公開CIは外部の実サイトを巡回せず、ローカルの制御したページで再現可能な条件を検査します。
外部CSSとHTML内のstyleタグ・style属性の参照、CSS import・クエリ違い・大文字拡張子・外部CDN・動的メニュー画像・外部/インラインJS・ES module import・レスポンシブ画像、送信遮断、キャッシュ破損、304再検証、途中失敗後の再開、quick/complete、オフライン表示を対象にしています。

実行方法は [共通CLIガイド](../skills/lp-copy/references/fast-capture.md) を参照してください。
